# 标题与角色选择完整演出改造设计

## 背景

当前标题/主菜单和角色选择界面均位于 `scenes/Root.tscn`，对应逻辑主要分布在 `TitleScreen.gd`、`MainMenu.gd`、`NewRunMenu.gd`、`CharacterButtonContainer.gd` 和 `CharacterSelectionButton.gd`。现有流程已经能够从主菜单进入新游戏并选择角色，但布局以静态控件为主，角色选择按钮仅承担头像展示，缺少连贯的场景演出和明确的焦点反馈。

本次采用已确认的方案 A：完整演出改造并同步新增配套美术资产。演出节奏、层次关系和选中反馈参考《杀戮尖塔》，但不复制其暗黑手绘美术。视觉继续使用项目现有的明快奇幻、浮岛世界和二次元角色立绘方向。机器人设定仅以遗迹结构、符文装置和少量机械纹样体现，不作为主视觉风格。

## 目标

1. 将当前标题界面明确为标题/主菜单，不加入账号登录流程。
2. 用分层背景、环境视差、标题入场和菜单反馈建立完整标题演出。
3. 让主菜单到角色选择成为同一舞台内的连续转场，而不是生硬切屏。
4. 以现有角色立绘为选人界面第一视觉焦点，完整展示名称、生命、金币、描述和初始遗物，并保留难度、种子和自定义规则配置。
5. 支持鼠标、触屏、键盘和手柄的一致焦点反馈。
6. 所有转场都可安全跳过，并能在快速输入、资源缺失或返回操作后落到稳定状态。
7. 抽离标题界面场景和动画职责，避免继续扩大 `Root.tscn` 与按钮脚本的职责。

## 非目标

1. 不实现账号、联网、存档云同步或用户身份系统。
2. 不修改角色战斗数值、初始卡组、遗物效果或开局地图规则。
3. 不重绘现有角色立绘和角色头像。
4. 不复制《杀戮尖塔》的角色、背景、字体、图标或界面资产。
5. 不新增配乐制作范围；现有 BGM 和 UI 音效接口只增加动画同步点。
6. 不建立新的全局 UI 框架，也不重构与标题流程无关的战斗、地图和事件界面。
7. 不重做现有图鉴和设置子菜单的内部布局；本轮只保证入口、返回和焦点行为在场景抽离后保持可用。

## 视觉基准

### 总体方向

- 主色来自晴朗天空、浮岛植被、浅色遗迹石材和角色自身阵营色。
- 背景使用通透的远近层次、清晰轮廓和柔和光照，兼容现有 Q 版角色立绘。
- 控件保持明亮、紧凑和易读，避免大面积工业面板、深色科幻舱室、霓虹终端和重机械框架。
- 机器人世界观只出现在远景遗迹的机械关节、能量符文、悬浮装置和装饰纹样中。
- 动画回弹控制在对象尺寸的 4% 至 8%，不使用长时间震屏、大面积闪白或持续抖动。

### 资产规格

标题背景新增到 `external/sprites/ui/title_screen/`，逻辑画布统一为 1200x700：

1. `title_sky.png`：不透明天空底层。
2. `title_far_islands.png`：透明远景浮岛层。
3. `title_mid_ruins.png`：透明中景遗迹层。
4. `title_platform.png`：透明角色站立平台层。
5. `title_foreground.png`：透明前景云、植被或装饰遮挡层。
6. `title_ornament.png`：不含文字的标题装饰底图；游戏名称继续由 Godot 文本节点渲染，保证文字准确且可维护。
7. `particle_soft.png` 与 `particle_spark.png`：环境粒子和确认反馈使用的小尺寸透明贴图。

角色选择背景采用同一透视结构的四个无角色、无文字、无 UI 版本，分别放入现有角色资源目录，并写入对应角色 JSON 的 `character_background_texture_path`：

- `external/sprites/characters/character_red/character_red_background.png`
- `external/sprites/characters/character_blue/character_blue_background.png`
- `external/sprites/characters/character_green/character_green_background.png`
- `external/sprites/characters/character_orange/character_orange_background.png`

四个背景只改变局部光色、装饰植物、符文或小型场景物件，不改变舞台地平线和角色落位区域。这样切换角色时可以淡变背景而不产生镜头跳动。

## 标题与主菜单布局

标题界面使用 1200x700 逻辑画布和全屏分层背景：

- 游戏名称位于左上至中左区域，以 `title_ornament.png` 承托，保持第一视口主信号。
- 主菜单位于左下区域，保留现有“继续游戏”“放弃当前流程”“新的冒险”“图鉴”“设置”“退出”入口。继续/放弃与新冒险继续按存档状态互斥显示。
- 右侧和中景保留角色群像或舞台视觉区域，不让菜单覆盖角色主体。
- 前景装饰跨越底边，用于建立景深，但不能遮挡按钮和焦点轮廓。
- 菜单默认焦点优先落在“继续游戏”；没有可继续存档时落在“新的冒险”。
- 菜单悬停或获得焦点时向右移动约 10 至 12 像素并提亮，按下时短暂缩放后回弹。

标题空闲状态包含低幅度持续动画：天空层不动，远景浮岛极慢横移，中景遗迹轻微视差，前景装饰缓慢摆动，粒子按固定上限循环。持续动画不得改变任何控件的布局尺寸和点击区域。

## 角色选择布局

角色选择继续处于同一标题舞台中，通过镜头推进和背景横移进入：

- 页面标题“选择冒险者”位于顶部中央。
- 左侧约 5% 至 35% 区域显示角色名称、生命、金币、描述和初始遗物。
- 选中角色立绘位于中央舞台，站位固定；立绘尺寸根据原图安全缩放，不裁切头部、武器、头发和脚部。
- 右侧约 70% 至 97% 区域作为运行配置区，保留难度步进、种子输入和自定义规则滚动列表。
- 角色头像队列位于底部偏右区域。获得焦点的头像向上抬升、显示阵营色轮廓，并与舞台角色同步。
- “开始冒险”和“返回”位于运行配置区底部，不与立绘、头像或详情面板重叠。
- 角色详情面板不嵌套额外卡片；使用一个信息底板和清晰的内部信息分区。

切换角色时，旧立绘轻微后退并淡出，新立绘从固定落位点弹性进入；角色背景进行短时交叉淡变，详情文字在同一帧更新后淡入。快速连续切换始终以最后一次输入选择为准。

## 演出时间线

### 标题首次进入

总时长目标为 1.05 秒：

1. `0.00-0.55s`：背景分层显现并启动视差。
2. `0.18-0.75s`：标题落位并产生一次轻微回弹。
3. `0.45-1.05s`：菜单逐项进入，相邻项目间隔约 60 毫秒。
4. `1.05s`：恢复默认焦点并开放完整输入。

### 主菜单进入角色选择

总时长目标为 0.80 秒：

1. `0.00-0.18s`：“新的冒险”产生按下反馈，菜单向左收拢。
2. `0.08-0.58s`：远景横移，镜头推进至角色平台。
3. `0.35-0.70s`：角色标题、头像队列和详情面板依次进入。
4. `0.52-0.80s`：默认角色落位，背景完成淡变，角色选择输入开放。

### 切换角色与确认开局

- 单次角色切换目标时长为 0.22 秒。旧角色退场、头像焦点移动、新角色落位和详情更新允许重叠执行。
- 确认开局目标时长为 0.65 秒。按钮先锁定，角色光环收束并产生确认反馈，随后 UI 退场并调用现有开局流程。
- 返回主菜单使用约 0.60 秒的反向转场，结束后将焦点恢复到“新的冒险”。

时间值是实现目标范围。允许为修正素材落位进行不超过 0.10 秒的局部调整，但不得将标题首次进入、菜单到选人或确认开局扩大成长时间不可操作的演出。

## 输入、跳过与焦点规则

1. 鼠标、触屏、键盘和手柄共享同一选中状态和视觉反馈。
2. 标题入场期间按确认、取消或再次点击，会立即完成标题入场并恢复焦点，不触发菜单命令。
3. 菜单到选人转场期间再次确认或点击，会立即完成该转场；取消会完成当前过渡后返回主菜单稳定状态。
4. 确认开局后忽略重复确认，保证现有开局流程只调用一次。
5. 角色切换动画可被新方向输入替换，最终选中角色必须与最后一次输入一致。
6. 跳过不直接设置零散属性，而是调用对应阶段的统一最终状态函数，确保可见性、位置、缩放、透明度、焦点和输入锁同时恢复。

## 场景与组件边界

### 场景结构

从 `scenes/Root.tscn` 抽离标题分支，新建 `scenes/ui/menus/TitleScreen.tscn`。`Root.tscn` 只负责实例化标题场景并接收开始游戏结果。

`TitleScreen.tscn` 包含以下职责节点：

- `Backdrop`：天空、远景、中景、平台、前景和环境粒子。
- `TitleLayer`：标题装饰、游戏名称和主菜单。
- `CharacterLayer`：选人标题、详情面板、角色舞台、头像队列和开始按钮。
- `UtilityLayer`：承载现有图鉴和设置子菜单，不在本轮重做其内部视觉。
- `TransitionOverlay`：只用于必要的淡变和确认反馈，不长期遮挡画面。

### 脚本职责

- `TitleScreen.gd`：标题流程协调器，持有界面状态，连接主菜单、选人和现有开局流程。
- 新建 `TitlePerformanceController.gd`：创建和取消 Tween，执行标题入场、菜单到选人、返回主菜单、确认开局，并提供每个阶段的最终状态函数。
- 新建 `MenuBackdrop.gd`：只负责空闲视差、低幅度环境运动和角色背景交叉淡变。
- `MainMenu.gd`：只负责菜单焦点、按钮状态和命令信号，不直接操作背景或角色节点。
- `NewRunMenu.gd`：管理角色列表、当前角色、详情刷新和开局确认，不直接编排全屏转场。
- `CharacterButtonContainer.gd`：根据角色数据创建头像按钮并维护焦点顺序。
- `CharacterSelectionButton.gd`：只处理单个头像的悬停、焦点、按下反馈和选择信号。

### 状态模型

`TitleScreen.gd` 使用明确状态限制输入：

- `ENTERING`
- `MAIN_MENU`
- `TO_CHARACTER_SELECT`
- `CHARACTER_SELECT`
- `TO_MAIN_MENU`
- `CODEX`
- `SETTINGS`
- `LEAVING`

任何状态转换前先取消旧 Tween，再由 `TitlePerformanceController.gd` 设置当前阶段起始状态。转场完成或跳过后统一进入目标稳定状态。

图鉴和设置沿用现有直接进入子菜单的流程，分别进入 `CODEX` 和 `SETTINGS`。返回时恢复 `MAIN_MENU` 及进入前的主菜单焦点。继续游戏和放弃当前流程仍调用现有 `FileLoader` 接口，不改变存档行为。

## 数据流

1. `FileLoader.gd` 继续加载 `external/data/characters/` 中的 JSON 并建立 `CharacterData`。
2. `CharacterButtonContainer.gd` 从现有全局角色集合创建头像按钮。
3. 默认角色确定后，`NewRunMenu.gd` 保存当前 `CharacterData`，刷新名称、生命、金币、描述和初始遗物。
4. `NewRunMenu.gd` 发出角色变化信号，`TitleScreen.gd` 将角色立绘、阵营色和 `character_background_texture_path` 交给舞台节点。
5. 舞台先准备新资源，再进行背景交叉淡变和角色切换，避免出现一帧空白。
6. 难度、种子和自定义规则继续由 `NewRunMenu.gd` 与 `CustomRunModifierButtonContainer.gd` 维护，角色切换不得重置这些配置。
7. 用户确认后，`NewRunMenu.gd` 将角色、种子、难度和自定义规则一起发出一次开局请求；`TitleScreen.gd` 将输入状态设为 `LEAVING`，完成确认演出后调用现有新游戏入口。

不新增角色 JSON 必填字段。现有 `character_texture_path`、`character_icon_texture_path`、`character_background_texture_path`、生命、金币、描述和初始遗物字段足以驱动新版界面。

## 错误处理与回退

1. 角色背景缺失：使用公共标题平台背景，不阻断选人。
2. 完整角色立绘缺失：回退到角色头像；立绘和头像均缺失时显示中性剪影占位。
3. 初始遗物资源缺失：显示通用遗物占位并记录警告，不阻断开局。
4. 角色集合为空或关键角色数据无法建立：显示“暂无可用角色”，禁用“开始冒险”，不调用开局流程。
5. 背景分层资源缺失：对应层保持隐藏，其余层继续显示；天空底层必须提供项目内默认纯色回退。
6. 快速输入导致旧 Tween 尚未完成：取消旧 Tween，调用当前阶段最终状态，再执行下一目标状态。
7. 窗口切出后恢复：根据 `TitleScreen.gd` 当前状态重新应用稳定布局，不依赖 Tween 剩余时间恢复界面。

## 性能约束

1. 标题和四个角色背景在进入标题场景时预加载，角色切换时不进行同步磁盘读取。
2. 环境粒子设置固定数量上限，空闲动画不得持续创建节点或 Tween。
3. 背景视差只修改已有节点位置，不改变 Control 最小尺寸，不触发布局抖动。
4. 角色背景保持与 1200x700 逻辑画布一致的基准尺寸，由 Godot 拉伸策略处理窗口缩放。
5. 转场完成后释放一次性 Tween 引用，并保证重复进入标题场景不会重复连接信号。

## 测试与验收

### 自动化回归

新增 `tests/title_screen_performance_regression.gd`，并扩展现有 `tests/ui_layout_bounds_regression.gd`：

1. 标题场景可在 headless 模式正常实例化，无缺失节点或资源错误。
2. 标题入场跳过后进入 `MAIN_MENU`，位置、透明度、缩放和焦点均为稳定值。
3. 主菜单进入角色选择后进入 `CHARACTER_SELECT`，默认角色数据与舞台展示一致。
4. 连续切换角色后，最终详情、立绘和背景对应最后一次输入。
5. 重复确认只产生一次开局请求。
6. 返回主菜单后恢复正确菜单可见性和“新的冒险”焦点。
7. 缺少角色背景、立绘或遗物资源时使用规定回退，不抛出运行错误。
8. 空角色集合会禁用开始按钮并显示空状态。
9. 1200x700 逻辑画布内，标题、菜单、详情面板、角色立绘、头像队列和开始按钮均不越界或重叠。
10. 1920x1080 窗口缩放下保持正确画布拉伸或留白，不出现文字裁切和焦点轮廓越界。
11. 继续游戏、放弃当前流程、图鉴、设置和退出入口在场景抽离后仍调用原有逻辑，图鉴与设置返回时恢复主菜单焦点。
12. 难度、种子和自定义规则在角色切换、返回再进入和确认开局时保持现有数据行为。

动画测试验证最终状态和信号次数，不依赖逐帧截图比较具体 Tween 中间帧，以避免时序测试不稳定。

### 视觉验收

1. 启动游戏并分别截取标题稳定态、角色选择稳定态和四个角色选中状态。
2. 确认现有角色立绘是选人界面第一视觉焦点，背景不会抢夺角色主体。
3. 确认标题和角色界面属于同一浮岛奇幻舞台，机器人元素只作为世界观细节出现。
4. 检查长角色名称、长描述、遗物名称和禁用按钮状态，保证文字不越界。
5. 使用鼠标、键盘和手柄走完进入、切换、返回和确认流程，反馈保持一致。
6. 在演出各阶段执行跳过和快速输入，界面不能停留在半透明、错位或无焦点状态。

## 完成标准

满足以下条件视为本轮完整演出改造完成：

1. 标题、主菜单和角色选择均使用批准的明快浮岛奇幻视觉，不以机器人风格作为主视觉。
2. 标题首次进入、菜单到选人、角色切换、返回和确认开局具有完整且可跳过的演出。
3. 四个现有角色均可正确显示立绘、背景、详情和选中反馈，难度、种子和自定义规则仍能参与开局。
4. 鼠标、触屏、键盘和手柄可以完成同一流程，默认焦点明确。
5. 重复确认、快速切换、资源缺失和窗口恢复不会造成重复开局或界面卡死。
6. 自动化回归通过，Godot headless 加载无场景错误，视觉截图检查无越界、遮挡和空白背景。
