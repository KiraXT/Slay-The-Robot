# 图鉴条目与通用悬浮说明底框视觉优化设计

## 背景

当前图鉴页面中敌人与遗物条目由 `scripts/ui/menus/CodexMenu.gd` 运行时创建，基础节点是未定制样式的 `PanelContainer`，因此在标题页背景上呈现为厚重灰色底板。截图中的悬浮说明也显得过宽、过高，和《杀戮尖塔》里紧凑的信息框相比遮挡面积过大。

这次调整需要覆盖两类界面：

- 图鉴页面的敌人、遗物条目底板。
- 游戏内所有通用 tooltip，包括图鉴条目、战斗顶部遗物、状态图标、资源按钮等使用 `tooltip_text` 或现有 `Tooltip` / `KeywordTooltip` 场景的说明框。

## 目标

- 去掉敌人和遗物图鉴条目的默认灰色面板，替换为符合当前 UI 的物件卡片底座。
- 将通用悬浮说明框改为紧凑、可读、遮挡更少的深色信息框，参考《杀戮尖塔》的说明框比例。
- 保持现有数据驱动内容不变，不改敌人、遗物、卡牌 JSON。
- 控制改动范围，避免影响卡牌本体渲染和战斗逻辑。

## 推荐方案

采用“浅色物件卡片 + 深色信息 tooltip”的组合。

图鉴敌人/遗物条目继续使用运行时创建方式，但 `_create_base_codex_entry()` 会显式注入 `StyleBoxFlat` 样式。底板使用接近白色的半透明底色、青色细边、轻微阴影和 8px 左右圆角，和现有卡牌内底、标题页按钮保持同一视觉语言。条目内容分成图片区、名称、元信息和描述，其中图片区使用轻底托突出图标或敌人头像，描述文本保持紧凑换行。

通用 tooltip 使用统一的深色底框。背景为低透明度深蓝黑，边框使用暖金色或青色细线，内边距比当前主题更小，默认宽度控制在约 260px。标题通过 BBCode 或文本首行处理保持高亮，正文保持 12-13px 字号并自动换行。这样 tooltip 更接近《杀戮尖塔》的战斗信息框：信息密度高、遮挡小、和亮色背景有明确对比。

## 组件设计

### 图鉴条目底板

`CodexMenu.gd` 增加少量样式常量和 helper：

- `CODEX_ENTRY_STYLE`：普通浅底卡片外框。
- `CODEX_ENTRY_IMAGE_STYLE`：图标区域浅底托。
- 可选的 hover / focus 样式：如果实现成本低，鼠标悬停时轻微提亮边框；否则首版只保证普通态。

条目尺寸保持当前 `150x220` 附近，避免重排整个图鉴布局。内部 margin 可从 8px 调整到 9-10px；图片区域继续使用 `112x88`，但用独立底托框住，避免图标漂浮在白底上。敌人条目显示名称、生命、类型/格挡/召唤物信息；遗物条目显示名称、稀有度/颜色和短描述。

### 通用 tooltip

`themes/keyword_tooltip_theme.tres` 改为深色 tooltip theme：

- `PanelContainer/styles/panel` 使用深色背景、细边框、较小圆角、较轻阴影。
- `RichTextLabel/colors/default_color` 使用浅色文字。
- `RichTextLabel/font_sizes/normal_font_size` 保持 12 或 13，确保多行说明不夸张。
- `Tooltip.tscn` 和 `KeywordTooltip.tscn` 的 `custom_minimum_size.x` 调整到约 260，不使用过大的固定高度。

为了覆盖 `tooltip_text` 产生的 Godot 默认说明框，需要给相关可交互控件提供统一的自定义 tooltip 入口。优先实现一个轻量 helper，用现有 `scenes/ui/general/Tooltip.tscn` 构造面板，并在图鉴条目、战斗遗物、消耗品、状态图标等已有 `tooltip_text` 使用点中复用。若发现 Godot theme 已能全局覆盖默认 tooltip，则不额外改每个控件；但必须通过运行验证确认战斗遗物和图鉴条目都使用新底框。

## 数据流

敌人和遗物数据仍来自现有 `Global.get_enemy_data()` 与 `Global.get_artifact_data()`。UI 层只读取现有字段并创建控件：

1. 用户打开图鉴敌人或遗物页。
2. `CodexMenu.gd` 清空容器并根据数据创建条目。
3. 条目创建时应用自定义底板样式，并设置或生成自定义 tooltip。
4. 鼠标悬停时显示统一 tooltip，内容来自当前 `tooltip_text` 等价文本。

战斗内遗物、状态、资源按钮继续由原节点负责设置说明文字；显示层统一转成新 tooltip 面板，不改变右键遗物、状态逻辑或资源点击逻辑。

## 错误处理

- 图片路径为空或加载失败时保持现有 `FileLoader.load_texture()` 行为，不新增数据兜底逻辑。
- tooltip 文本为空时不显示额外面板。
- 文本过长时依赖自动换行和固定宽度限制；不允许 tooltip 横向扩张遮挡大半屏。
- 如果某个控件已有特殊 tooltip 逻辑，保留其内容生成方式，只替换外观底框。

## 测试与验证

- 增加或更新一个 UI 回归测试，实例化图鉴菜单并检查敌人/遗物条目的 `PanelContainer` 存在显式样式覆盖，不再依赖默认灰色 panel。
- 检查 tooltip 场景宽度、theme panel 样式、文字颜色和边距符合设计约束。
- 运行相关 Godot headless 测试，至少覆盖新增/更新的 UI 回归测试；若测试环境允许，补充标题页图鉴打开后的截图验证。
- 手动视觉验证重点：图鉴敌人页、图鉴遗物页、战斗顶部遗物 tooltip、状态图标 tooltip。

## 非目标

- 不重做卡牌图鉴条目的卡牌渲染。
- 不替换敌人、遗物、状态图标图片资源。
- 不调整标题页背景、图鉴分页结构、滚动区域布局。
- 不引入新的图片九宫格资源，首版使用 Godot 样式框完成底板。
