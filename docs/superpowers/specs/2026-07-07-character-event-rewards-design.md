# 四角色专属事件奖励设计

**目标：** 按当前四个角色的玩法设定，补充首批非战斗事件设定和选项奖励。本文只定义事件设计清单，不直接新增运行时 JSON。

**范围：** 每个角色 2 个专属事件，共 8 个事件；每个事件 3 个选项。奖励优先使用现有动作可以表达的内容：金币、生命、消耗品、抽选卡牌、移除卡牌、升级卡牌、转换卡牌。

## 设计原则

1. 事件先服务角色玩法识别，而不是做通用奖励池。
2. 每个角色事件都对应其当前卡牌边界：
   - 红：近身连段、压迫、爆发。
   - 蓝：抽弃循环、混乱补救、随机资源。
   - 绿：节奏控制、腐蚀、成长。
   - 橙：准备、保留、抽到触发、消耗兑现。
3. 首批不引入新底层奖励机制，避免事件设计先超过现有配置能力。
4. 单个选项的代价和收益保持清楚：生命换强奖励，金币换定向奖励，免费选项给轻量资源。
5. 事件文字保持短、直接，后续落地时可再扩写为 BBCode 提示。

## 角色专属落地约束

目前事件池可以挂在 `act_non_combat_event_pool_object_id`，但项目尚未提供直接按当前角色过滤事件的校验器。后续落 JSON 时有两条可选路线：

- 新增角色校验器，例如 `ValidatorCharacter.gd`，让事件通过 `event_pool_validator_data` 限定角色。
- 在地图生成或角色初始化阶段，为不同角色接入不同非战斗事件池。

本文按“角色专属事件”设计内容。后续实现前需要确认采用哪条接入路线。

## 奖励表达对照

这些奖励都能用现有数据动作表达，或只需要组合现有动作：

| 奖励 | 配置表达 |
|---|---|
| 获得或失去金币 | `ActionAddMoney` |
| 失去生命或治疗 | `ActionAddHealth` / `ActionHealPercent` |
| 获得消耗品 | `ActionAddConsumable` |
| 从指定颜色卡中选 1 张加入牌组 | `ActionPickCards` 草稿选择 + `ActionAddCardsToDeck` |
| 获得指定颜色稀有牌 | `ActionPickCards` + `ValidatorCardColor` + `ValidatorCardRarity` |
| 升级牌组中的牌 | `ActionPickUpgradeCards` 或 `ActionPickCards` + `ActionUpgradeCards` |
| 移除牌组中的牌 | `ActionPickCards` + `ActionRemoveCardsFromDeck` |
| 转换牌组中的牌 | `ActionPickCards` + `ActionTransformCards` |

## 事件清单

### 红色角色

红色事件强调训练、突破和正面对抗。奖励偏向攻击牌、升级攻击牌和直接资源。

#### 1. 破损拳击台

**事件 ID 建议：** `event_red_broken_boxing_ring`

**场景：** 废弃训练场里还有一台会反击的拳击测试机器人。它的记分屏闪烁着红色警告，只要出拳，它就会回击。

| 选项 | 文案 | 奖励/代价 | 设计意图 |
|---|---|---|---|
| 重打基础 | 站稳，重新练一遍基础拳路。 | 失去 6 生命，升级 1 张攻击牌。 | 用生命换红色核心成长。 |
| 压上步伐 | 靠近机器，抢在它反击前连续出手。 | 失去 30 金币，从 3 张红色攻击牌中选 1 张加入牌组。 | 补连段牌，代价是资源。 |
| 拆下护板 | 不练了，把机器外壳拆下来卖掉。 | 获得 50 金币。 | 提供保守经济选项。 |

#### 2. 红线警戒门

**事件 ID 建议：** `event_red_warning_line_gate`

**场景：** 一扇门前投射着红色警戒线。系统不断播报“只允许攻击姿态通过”，门后的奖励箱已经半开。

| 选项 | 文案 | 奖励/代价 | 设计意图 |
|---|---|---|---|
| 正面突破 | 不等系统识别，直接撞开门。 | 失去 10 生命，获得 1 张红色稀有牌。 | 高风险高上限，符合红色压迫感。 |
| 找准破绽 | 等门禁扫描间隔，打穿薄弱点。 | 从 3 张红色牌中选 1 张加入牌组。 | 标准定向补牌。 |
| 暂时撤退 | 记下路线，拿走门边的防护罐。 | 获得 1 个格挡药剂。 | 防守向低风险选项。 |

### 蓝色角色

蓝色事件强调翻找、回收和不稳定收益。奖励偏向弃牌相关卡、随机资源、转换和移除。

#### 3. 散落的工具箱

**事件 ID 建议：** `event_blue_scattered_toolbox`

**场景：** 一个工具箱翻倒在走廊中央，螺丝、线缆、备用电池和不明零件滚得到处都是。

| 选项 | 文案 | 奖励/代价 | 设计意图 |
|---|---|---|---|
| 慌忙翻找 | 把能用的东西先抓进包里，之后再整理。 | 从 3 张蓝色牌中选 1 张加入牌组，随机移除 1 张可移除牌。 | 蓝色的混乱补救，收益和不确定性并存。 |
| 留下备用品 | 只拿最像急救工具的那几件。 | 获得 1 个随机消耗品。 | 支持蓝色临时工具轴。 |
| 卖掉零件 | 不研究了，把零件按重量出售。 | 获得 60 金币。 | 纯经济选项。 |

#### 4. 失控洗牌机

**事件 ID 建议：** `event_blue_runaway_shuffler`

**场景：** 一台旧洗牌机还在工作。它吸入卡牌、吐出卡牌，偶尔还会把标签贴错。

| 选项 | 文案 | 奖励/代价 | 设计意图 |
|---|---|---|---|
| 接受重排 | 让机器处理一张不顺手的牌。 | 转换 1 张牌。 | 蓝色混乱重构。 |
| 抓住弹出的牌 | 在机器吐牌的瞬间抓住一张。 | 从 3 张蓝色牌中选 1 张加入牌组。 | 稳定补蓝色循环组件。 |
| 关掉机器 | 买下停机权限，清理卡组。 | 失去 40 金币，移除 1 张牌。 | 用资源换精简牌组。 |

### 绿色角色

绿色事件强调节奏、调音、腐蚀样本和持续成长。奖励偏向技能升级、绿色牌和药剂。

#### 5. 回声调音室

**事件 ID 建议：** `event_green_echo_tuning_room`

**场景：** 破旧音响在小房间里循环播放一段节拍。每次节拍落下，墙上的仪表都会同步闪一下。

| 选项 | 文案 | 奖励/代价 | 设计意图 |
|---|---|---|---|
| 跟上第一拍 | 按节奏调整动作，只练最稳定的一段。 | 升级 1 张技能牌。 | 对应绿色节奏和防御成长。 |
| 调整频率 | 扭动旋钮，让声音变成可用的战术。 | 从 3 张绿色牌中选 1 张加入牌组。 | 补绿色核心组件。 |
| 过载共鸣 | 把音量推到红线，让身体记住这段节奏。 | 失去 8 生命，获得 1 张绿色稀有牌。 | 生命换高上限成长牌。 |

#### 6. 腐蚀培养槽

**事件 ID 建议：** `event_green_corrosion_tank`

**场景：** 玻璃槽里残留着会慢慢侵蚀金属的试剂。槽壁上写着“低剂量稳定，高剂量危险”。

| 选项 | 文案 | 奖励/代价 | 设计意图 |
|---|---|---|---|
| 提取试剂 | 小心装走一管仍可使用的腐蚀液。 | 获得 1 个伤害药剂和 30 金币。 | 轻量进攻奖励。 |
| 强化样本 | 用试剂激活一张绿色牌的潜力。 | 失去 5 生命，升级 1 张绿色牌。 | 绿色成长但有代价。 |
| 封存危险品 | 不冒险，把稳定剂带走。 | 获得 1 个治疗药剂。 | 保守生存选项。 |

### 橙色角色

橙色事件强调赛前准备、背包装备、保留和消耗兑现。奖励偏向橙色牌、移除、消耗品和升级。

#### 7. 赛前补给站

**事件 ID 建议：** `event_orange_prep_supply_stop`

**场景：** 一处自动补给站还亮着灯。货架上有饮料、旧护具和临时路线图，但每个格子都快卡住了。

| 选项 | 文案 | 奖励/代价 | 设计意图 |
|---|---|---|---|
| 打包饮料 | 先拿最容易入口的补给。 | 获得 1 个治疗药剂，并获得 1 张橙色普通牌。 | 对应橙色补给和准备。 |
| 轻装上阵 | 丢掉累赘，只保留最重要的东西。 | 失去 50 金币，移除 1 张牌。 | 牌组压缩，支持准备流。 |
| 多拿一点 | 多塞几件补给进背包，动作变慢一点。 | 失去 6 生命，获得 2 个随机消耗品。 | 高资源但有生命代价。 |

#### 8. 旧背包夹层

**事件 ID 建议：** `event_orange_hidden_backpack_pocket`

**场景：** 旧背包夹层里藏着票据、备用卡和一枚小徽章。很多东西已经过期，但仍然有用。

| 选项 | 文案 | 奖励/代价 | 设计意图 |
|---|---|---|---|
| 夹好书签 | 把一张常用牌固定在最顺手的位置。 | 升级 1 张橙色牌。 | 强化准备核心。 |
| 翻出旧物 | 找出还能派上用场的旧装备。 | 从 3 张橙色牌中选 1 张加入牌组。 | 标准橙色补牌。 |
| 卖掉纪念品 | 把徽章和票据打包卖掉，顺手清空一件旧物。 | 获得 75 金币，随机移除 1 张可移除牌。 | 经济和精简并存，但不可控。 |

## 数值基准

首批事件使用温和数值，避免非战斗事件过度决定构筑：

| 奖励类型 | 建议范围 |
|---|---|
| 免费金币 | 50-75 |
| 生命代价 | 5-10 |
| 金币代价 | 30-50 |
| 普通定向选牌 | 3 选 1 |
| 稀有牌奖励 | 通常需要生命代价 |
| 移除牌 | 通常需要金币代价，或随机化作为免费/收益附带 |
| 消耗品 | 1 个为低风险奖励，2 个需要生命代价 |

## 后续实现注意事项

1. 如果要让事件真正只对对应角色出现，需要先确定角色限定方案。
2. 如果采用事件池过滤，建议新增 `ValidatorCharacter.gd`，否则当前数据中没有稳定的角色过滤器。
3. 如果采用角色专属事件池，需要在章节或地图生成逻辑里接入不同非战斗池。
4. 这些事件的 `event_dialogue_data` 可以直接内嵌在事件 JSON 中，不必新增独立 `dialogue` JSON。
5. Excel 事件转换器目前不适合承载复杂动作，后续落地建议直接写 JSON，或先扩展转换器。

## 验收标准

1. 首批事件共 8 个，每个角色 2 个。
2. 每个事件至少有一个角色机制相关奖励。
3. 每个事件至少有一个低风险或保守选项。
4. 奖励都能映射到现有动作，除“角色专属接入”外不要求新底层机制。
5. 后续落 JSON 时，事件文案、选项奖励、代价和 ID 可从本文直接迁移。

## 不在本轮范围

- 直接创建 `external/data/events/*.json`。
- 更新 `external/data/event_pools/*.json`。
- 新增角色事件校验器。
- 制作事件插图。
- 最终数值平衡。
