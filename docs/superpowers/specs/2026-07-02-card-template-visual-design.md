# 卡牌模板视觉迭代设计

## 背景

当前卡牌 UI 位于 `scenes/ui/Card.tscn`，显示逻辑位于 `scripts/ui/Card.gd`。卡牌尺寸为 144x184，数据来自 `CardData`：费用、名称、描述、类型、稀有度、颜色和卡图都已经由现有字段提供。用户希望参考弹射世界卡牌模板框架，对当前游戏卡牌进行设计迭代：卡牌颜色要和角色颜色对应，阵营用角色形象提取关键词设计，稀有度用星级表示，并且不能出现文字超框。

本设计采用已确认的 B 方案：亮色模块。它保留参考图的清晰信息分区，同时适配当前 Godot 小尺寸卡牌和中文文本。

## 目标

1. 将卡牌视觉重排为亮色模块结构：费用、卡名、卡图、类型、效果、星级、阵营徽记都有稳定位置。
2. 卡牌主色继续跟随 `card_color_id`，并与现有角色色系对应。
3. 阵营徽记不新增必填数据字段，先由 `card_color_id` 推导关键词。
4. 稀有度从文字显示改为星级显示。
5. 保持现有卡牌尺寸、交互信号和战斗逻辑不变。
6. 名称、类型、描述不能溢出各自显示区域。

## 非目标

1. 不重做卡牌插画资源。
2. 不修改卡牌战斗逻辑、拖拽逻辑、悬停关键词逻辑或卡牌动作数据。
3. 不要求批量改写 `external/data/cards/` 中的 JSON。
4. 不引入新的全局 UI 框架或主题系统。
5. 不改变卡牌在手牌、奖励、商店、牌库查看等界面的基础尺寸契约。

## 视觉结构

单张卡牌保持 `Control` 根节点 144x184，不改变外部布局依赖。内部视觉区域采用以下层级：

1. 外框：圆角 7px 左右的亮色卡框，边框色由卡牌颜色派生。
2. 费用徽章：左上角圆形徽章，支持数字费用和 X 费用。
3. 卡名条：顶部横向标题区域，给费用徽章和阵营徽记留出左右安全距离。
4. 阵营徽记：右上角圆形小徽章，显示一个由阵营关键词提取的汉字。
5. 卡图区域：中上部矩形卡图，使用现有 `card_texture_path`；缺图时继续显示默认纹理或空白占位。
6. 类型条：卡图下方彩色胶囊条，仅显示卡牌类型，不再拼接稀有度文字。
7. 描述区：类型条下方的大面积文本框，居中显示效果文本。
8. 星级条：底部左侧显示稀有度星级。

推荐布局比例以当前 144x184 为基准：

- 费用徽章：约 32x32，略微压住左上角。
- 卡名条：顶部 18-22px 高，左右避开费用和阵营徽记。
- 卡图区域：约 120x70，放在卡名条下方。
- 类型条：约 120x18-20。
- 描述区：约 120x40-46。
- 星级条：底部 12-14px 高。

## 颜色规则

主色继续使用 `Global.get_color_data(card_data.card_color_id)` 获取。视觉层基于主色派生浅底、深边和类型条颜色。初始映射如下：

| card_color_id | 角色/阵营关键词 | 徽记字 | 视觉倾向 |
| --- | --- | --- | --- |
| color_red | 拳击、爆发、近战 | 拳 | 红色边框，攻击感强 |
| color_green | 自然、藤蔓、腐蚀 | 藤 | 绿色边框，回复/腐蚀感 |
| color_blue | 流动、能量、抽牌 | 流 | 蓝色边框，法术/节奏感 |
| color_orange | 机械、强化、结构 | 械 | 橙色边框，工程/强化感 |
| color_white | 核心、基础、通用 | 核 | 白/浅灰边框，基础牌感 |
| color_purple | 暗蚀、诅咒、异常 | 蚀 | 紫色边框，负面/特殊感 |

若遇到未登记颜色，阵营徽记显示 `?`，边框仍使用原始颜色。

## 稀有度星级

稀有度从 `card_rarity` 推导星级，不再把稀有度文本放入类型栏。

| CardData.CARD_RARITIES | 星级 |
| --- | --- |
| BASIC | 1 星 |
| COMMON | 2 星 |
| UNCOMMON | 3 星 |
| RARE | 4 星 |
| GENERATED | 0 星 |

实现优先使用可控的 `Label` 文本显示星号，避免引入新图片依赖。若后续需要更精致，可再替换为星形贴图或图标节点。

## 文本约束

卡名和描述继续使用 `RichLabelAutoSizer`，并保持 `clip_contents`、`scroll_active = false`、智能换行。实现时需要保证：

1. 卡名最大字号约 12，最小字号不低于 8；超长卡名在标题区域内缩字号，必要时裁剪。
2. 描述最大字号约 11-12，最小字号不低于 7；长文本优先自动缩字号，不允许向下覆盖星级。
3. 类型条使用普通 `Label`，文本只显示类型中文名或现有枚举名，保持单行居中。
4. 描述区必须与类型条、星级条有固定间距，不能依赖文本内容动态撑开布局。
5. 卡图和文本区域均设置稳定尺寸，悬停、升级名、X 费用不会改变卡牌整体尺寸。

## 数据流

`Card.gd.update_card_display()` 继续作为唯一刷新入口。刷新流程扩展为：

1. 读取并设置卡图。
2. 设置卡名：`card_data.get_card_name()`。
3. 设置描述：`get_card_description(selected_enemy)`。
4. 设置类型：只从 `card_type` 推导类型文本。
5. 设置主色：从 `card_color_id` 读取 `ColorData`。
6. 设置阵营徽记：从 `card_color_id` 映射关键词字。
7. 设置星级：从 `card_rarity` 映射星号数量。
8. 设置费用：沿用现有数字/X/X-N 逻辑。
9. 设置可打出状态：沿用现有 `card_is_playable` 控制费用显示。

## 组件边界

主要修改：

- `scenes/ui/Card.tscn`：调整节点结构、位置、颜色层和新增星级/阵营节点。
- `scripts/ui/Card.gd`：新增少量 helper，用于类型文本、星级文本、阵营文本和颜色派生。

不修改：

- `CardData.gd` 的数据结构。
- `FileLoader.gd` 的 JSON 加载流程。
- `Hand.gd` 的拖拽和打牌流程。
- 卡牌 JSON 的行为字段和动作脚本。

## 错误处理与兼容

1. 缺少 `ColorData`：使用白/灰默认色，阵营徽记显示 `?`。
2. 缺少卡图：沿用当前默认纹理行为。
3. 未知稀有度：显示空星级，不报错。
4. 未知类型：显示枚举名或空文本，不影响卡牌可用性。
5. 旧卡牌 JSON 不需要迁移；已有 `card_color_id` 和 `card_rarity` 足够驱动新版 UI。

## 测试与验收

实现完成后需要验证：

1. Godot headless 能正常加载项目，无场景资源错误。
2. 至少抽查红、绿、蓝、橙、白、紫色卡牌，确认主色和阵营徽记正确。
3. 抽查 BASIC、COMMON、UNCOMMON、RARE、GENERATED 稀有度，确认星级显示符合规则。
4. 抽查长卡名、长描述、升级后带 `+` 的卡名，确认不超框、不覆盖类型条或星级条。
5. 在战斗手牌、奖励选牌、商店/牌库查看等复用卡牌场景里确认交互区域仍匹配卡牌视觉。
6. 费用数字、X 费用、不可打出卡牌的费用显示逻辑与现有行为一致。

## 实施顺序建议

1. 先改 `Card.tscn` 节点和固定布局。
2. 再改 `Card.gd` 的显示 helper 和刷新绑定。
3. 使用现有卡牌数据做本地视觉验证。
4. 如发现文本仍偏挤，只调整节点尺寸和 autosizer 上下限，不扩大卡牌外部尺寸。
