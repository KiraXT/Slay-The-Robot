# 地图错落布局设计

## 背景

当前地图生成已经支持每层 3-5 个节点和基础分叉连通，但节点坐标仍按固定网格居中排列：同层节点共线，跨层节点对齐成列，路线大多是规则直线。截图中还能看到顶部节点接近面板边界，整体观感偏机械，不像《杀戮尖塔》地图的自然爬升路线。

## 目标

让地图保持现有可玩结构和数据模型，同时获得更自然的错落感：

- 同一层节点有轻微上下浮动，不再完全共线。
- 跨层节点有横向扰动，不再严格落在固定列。
- 路线仍由 `location_next_location_ids` 决定，但绘制时带轻微折线或弧线感。
- 起点和 BOSS 保持居中，保证入口与终点稳定。
- 所有节点仍在地图可滚动区域内，不被面板裁切。

## 非目标

- 不重做地图图结构算法。
- 不改变 `LocationData` 存档字段。
- 不重平衡楼层类型分布、事件池、商店/篝火/精英出现规则。
- 不改变玩家实际可走路径，只改变节点坐标和路线视觉。

## 方案

### 节点坐标

在 `ActionGenerateAct.gd` 中保留现有 `_get_location_position()` 的基础网格坐标，但为普通楼层节点增加受世界生成 RNG 控制的偏移。

偏移规则：

- 横向偏移约为 `GRID_SPACING` 的 25%-40%，用于打破列对齐。
- 纵向偏移约为 `GRID_SPACING` 的 10%-20%，用于打破行对齐。
- 偏移只应用于普通楼层节点；起点和 BOSS 不偏移。
- 每个节点偏移后进行边界钳制，保证节点不会进入地图左侧负值，也不会超出主地图绘制宽度。
- 同层节点生成后按 X 坐标保持从左到右排序，避免路线连接算法因为扰动产生反直觉跳线。

为了保持稳定复现，偏移必须使用 `rng_world_generation`，不能用全局随机或时间随机。

### 路线绘制

在 `MapRouteLayer.gd` 中保留 `route_segments` 输入格式，扩展每条路线的绘制方式：

- 继续用 `from` 和 `to` 两端点作为真实连接依据。
- 根据端点生成一个确定性的中间控制点。
- 绘制虚线时沿两段短线或采样曲线绘制，而不是单条完全笔直的线。
- 控制点偏移幅度保持克制，避免路线穿过太多节点或显得杂乱。

这只影响视觉，不改变 `LocationData.location_next_location_ids`。

### UI 边界

`Map.gd` 继续根据最大 X/Y 设置 `LocationContainer` 大小。因为节点会偏移，容器尺寸计算需要继续用实际 `location_position`，并保留底部边距。实现时要确认顶部节点不会被 `ScrollContainer` 初始可视区域裁掉。

## 测试

新增或扩展地图回归测试：

- `tests/map_generation_flow_regression.gd`
  - 验证生成地图仍有唯一起点和 BOSS。
  - 验证所有节点仍可从起点到达。
  - 验证普通楼层节点数量仍在 3-5。
  - 验证普通楼层不再全部共用同一个 Y 坐标。
  - 验证节点 X 坐标不再全部落在 `GRID_SPACING` 固定列上。
  - 验证节点位置在合理地图边界内。

- `tests/map_location_layout_regression.gd`
  - 验证路线层仍在节点下方。
  - 验证路线段数量仍等于数据连接数量。
  - 验证路线层能接受并暴露路线段数据，便于回归检查。

## 风险与处理

- **节点重叠**：偏移幅度限制在小于半个网格，并保留原始居中间距，降低重叠概率。
- **路线过乱**：控制点偏移幅度受限，并保持端点确定性，避免每次刷新变化。
- **可达性回归**：不改变连接数据结构，仍由现有连通性测试覆盖。
- **存档兼容**：只改变新生成地图的位置；旧存档已有 `location_position` 时不会被自动重排。

## 验收标准

- 同一 seed 生成结果稳定。
- 地图截图中节点不再呈明显矩阵排列。
- 路线有自然错落感，但仍能清楚看出可走路径。
- 地图相关 Godot 回归测试通过。
